# 一、测试目标

## 1.1 测试愿景

```
保证产品质量 → 提升用户体验 → 持续交付价值
```

## 1.2 测试范围

| 测试类型 | 覆盖范围 | 测试目标 |
|---------|---------|---------|
| 单元测试 | 核心业务逻辑 | > 80% 覆盖率 |
| 集成测试 | API 接口、数据存储 | 关键路径覆盖 |
| E2E 测试 | 核心用户流程 | 关键流程通过 |
| AI 效果测试 | Agent 输出质量 | 人工评估 + 自动评估 |

## 6.2 GitHub Actions 配置

```yaml
# .github/workflows/ci.yml
name: CI

on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main]

jobs:
  test:
    runs-on: ubuntu-latest
    
    services:
      postgres:
        image: postgres:18
        env:
          POSTGRES_PASSWORD: test
        options: >-
          --health-cmd pg_isready
          --health-interval 10s
          --health-timeout 5s
          --health-retries 5
      
      redis:
        image: redis:7
        options: >-
          --health-cmd "redis-cli ping"
          --health-interval 10s
          --health-timeout 5s
          --health-retries 5

    steps:
      - uses: actions/checkout@v4
      
      - name: Set up JDK 21
        uses: actions/setup-java@v4
        with:
          distribution: 'temurin'
          java-version: '21'
      
      - name: Run Unit Tests
        run: ./gradlew test
        
      - name: Run Integration Tests
        run: ./gradlew integrationTest
        
      - name: Upload Coverage
        uses: codecov/codecov-action@v3
```

# 七、AI 效果评估

## 7.1 评估指标

| 指标 | 说明 | 评估方式 |
|-----|------|---------|
| 准确性 | 输出内容是否正确 | 人工评估 |
| 相关性 | 输出是否与输入相关 | 人工评估 + 自动评估 |
| 流畅性 | 输出语言是否流畅 | 人工评估 |
| 实用性 | 输出是否可使用 | 人工评估 |
| 响应时间 | 生成速度 | 自动统计 |

## 7.2 评估标准

### 7.2.1 打招呼话术评分标准

| 维度 | 权重 | 评分标准 |
|-----|-----|---------|
| 个性化 | 30% | 话术与JD/简历相关程度 |
| 完整性 | 20% | 包含必要信息程度 |
| 流畅性 | 20% | 语言自然程度 |
| 长度合适 | 15% | 100-200字范围 |
| 引导性 | 15% | 是否有后续沟通引导 |

### 7.2.2 聊天回复评分标准

| 维度 | 权重 | 评分标准 |
|-----|-----|---------|
| 准确性 | 30% | 回复内容正确程度 |
| 适当性 | 25% | 回复符合场景程度 |
| 专业性 | 20% | 回复专业程度 |
| 礼貌性 | 15% | 语气礼貌程度 |
| 效率 | 10% | 回复效率 |

## 7.3 人工评估流程

```
1. 随机抽样输出样本
2. 评估人员独立评分
3. 计算平均分
4. 低于阈值则触发优化
```

| AI 输出不稳定 | 中 | 高 | 增加评估样本量，多次测试 |
| 测试环境不稳定 | 中 | 低 | 容器化部署，自动化恢复 |
| 测试数据不足 | 中 | 中 | 提前准备测试数据 |
| 人员不足 | 高 | 低 | 合理分配任务，优先级排序 |

```
1. 核心功能（登录、简历、打招呼、聊天、投递）
2. 最近修改的功能
3. 相关联的功能
4. 边界条件测试
```
