## 1. 结论（先看这）

| 问题 | 答案 |
|------|------|
| V1 还缺不缺功能？ | **不缺**。求职闭环靠用户粘贴即可。 |
| V2 要解决什么？ | 少粘贴、可半自动：平台数据进系统、话术一键回填，**不**偷偷爬号发消息。 |
| 能不能直接爬 BOSS？ | **不能作为默认路径**。未获平台授权的自动化登录/采集/群发有封号与合规风险；本方案默认走「官方/合作 API」或「用户本机、用户在场的半自动」。 |
| 仓库现状 | 工作区**没有** `ai-job-hunter-agent`；Python Agent 待建独立仓，V1 不依赖它。 |

## 2. 产品目标与非目标

### 2.1 目标（V2）

1. **少粘贴**：岗位 / 聊天内容尽量从「已授权通道」进入系统。  
2. **半自动优先**：AI 生成话术 → 用户确认 → 再发送（或本机助手代填）。  
3. **可插拔平台**：先抽象 `PlatformConnector`，首个落地优先**有打招呼额度友好 / 可合规接入**的渠道（如猎聘官方或开放合作）；BOSS 仅在有官方授权后接入。  
4. **与现有 AI Agent 复用**：JD / Match / Greet / Chat 仍在 Java Spring AI；平台侧只负责「取数 / 填表 / 状态回写」。

### 2.2 非目标（V2 明确不做）

- ❌ 无官方授权的云端代登、批量爬 JD、自动群发打招呼  
- ❌ 把用户 Cookie / 密码存进云端明文库  
- ❌ 替换 V1 粘贴路径（粘贴永远保留作兜底）  
- ❌ 一次上全平台（拉勾 / 智联等放到 V2.x 扩展）

## 3. 合规与安全边界（红线）

| 级别 | 规则 |
|------|------|
| P0 | 不上线「绕过验证码 / 破解风控 / 未授权 API 抓包」类能力 |
| P0 | 云端永不存 BOSS/猎聘明文密码；会话凭证仅本机或用户可控密钥加密，且可一键吊销 |
| P0 | 默认模式 = **半自动**；全自动须用户显式开启 + 每日限额 + 可审计日志 |
| P1 | 遵守各平台用户协议与当地法律；文档与 UI 写明风险 |
| P1 | Agent 与后端通信必须鉴权（沿用 V1：`/api/v1/agent/**` 须登录） |
| P2 | 操作审计：谁、何时、对哪家平台、发了什么（脱敏） |

> 与 `02-TDS.md` §十七 对齐：~~无授权的 BOSS 全自动~~ 标为更晚阶段；V2 先做「合规接入 + 半自动」。

## 4. 架构（目标态）

```
┌────────────┐     JWT      ┌──────────────────┐
│  Nuxt SPA  │ ───────────► │  Spring Boot BE  │
│ 半自动确认  │ ◄── SSE/轮询 │  业务 + Spring AI │
└────────────┘              └────────┬─────────┘
                                     │ 内网 / 本机回调
                                     ▼
                            ┌──────────────────┐
                            │ Platform Agent   │
                            │ (Python，本机或  │
                            │  用户侧容器)     │
                            │  • Connector API │
                            │  • Playwright*   │
                            │  • 任务队列      │
                            └──────────────────┘
* Playwright 仅用于「用户在场 / 本机」半自动填表；云端批量爬取不在范围。
```

### 4.1 职责切分

| 组件 | 职责 |
|------|------|
| 前端 | 连接向导、任务进度、确认发送、风险提示 |
| 后端 | 用户/岗位/对话/投递 CRUD；调度任务状态；调用现有 LLM Agent |
| Platform Agent | 执行「登录态检测、列表同步、页面填入」等平台动作；**不**直接调 DeepSeek（避免双计费与密钥扩散） |

### 4.2 建议仓库

| 路径 | 说明 |
|------|------|
| `ai-job-hunter-be/` | 已有；增 `platform_*` 表与 API |
| `ai-job-hunter-fe/` | 已有；增「平台连接 / 待确认动作」页 |
| `ai-job-hunter-agent/` | **新建**；Python 3.11+、Playwright、与 BE 的任务协议 |

### 4.3 任务协议（草案）

```json
{
  "task_id": "uuid",
  "user_id": "uuid",
  "platform": "liepin|boss|manual",
  "action": "SYNC_JOBS|DRAFT_GREET|FILL_REPLY|MARK_APPLIED",
  "payload": {},
  "mode": "SEMI_AUTO|FULL_AUTO",
  "status": "PENDING|NEED_CONFIRM|RUNNING|DONE|FAILED"
}
```

- `SEMI_AUTO`：Agent 准备好草稿 → 状态 `NEED_CONFIRM` → 用户点确认 → Agent 执行。  
- `FULL_AUTO`：仅白名单动作 + 日限额；V2.0 可不实现。

## 5. 分阶段交付

### 阶段 A — 骨架（约 1 周）

- [ ] 新建 `ai-job-hunter-agent` 空仓 + README + 与 BE 的健康检查心跳  
- [ ] BE：`platform_connection` / `platform_task` 表设计写入 `04-ER-DESIGN.md`  
- [ ] API：创建连接、列任务、确认任务（无真实平台动作）  
- [ ] FE：占位页「平台连接（即将开放）」+ 任务列表 UI  
- [ ] 门禁：`PlatformTaskLiveIT` 冒烟 + FE e2e 占位  

**验收**：不连任何招聘站，端到端能走完「建任务 → 确认 → 完成（mock）」。

### 阶段 B — 首个合规连接器（约 2 周）

- [ ] 选定首平台（默认候选：**猎聘开放/合作 API**；若不可得则改为「本机导入 HTML/导出文件」）  
- [ ] 实现 `SYNC_JOBS`：岗位进入现有 `jobs`（`source=PLATFORM`）  
- [ ] 复用 `JdAnalyzerAgent` / `MatchAgent` / `GreetAgent`  
- [ ] 半自动：生成打招呼 → 用户确认 → 连接器执行「发送」或「复制到剪贴板」  

**验收**：用户能从平台同步 ≥1 个岗位并完成一次半自动打招呼（或剪贴板回填）。

### 阶段 C — 聊天半自动（约 1～2 周）

- [ ] 同步/导入会话消息到 `conversations`  
- [ ] `ChatAgent` 建议 → 确认 → 回填  
- [ ] 投递状态与看板联动（仍可手动改）  

### 阶段 D — BOSS（更晚，需授权）

- [ ] 仅在取得官方/明确授权后启动  
- [ ] 单独威胁建模与限额；默认仍半自动  
- [ ] 文档与 UI 单独风险页  

> 对应 `02-TDS.md`：无授权 BOSS 全自动 **不属于 V2 默认交付**。

## 7. 数据模型增量（草案，实现前再落 ER）

```
platform_connection
  id, user_id, platform, status, meta(jsonb), last_sync_at, created_at

platform_task
  id, user_id, connection_id, action, mode, status,
  request(jsonb), result(jsonb), error, created_at, updated_at
```

密钥类字段：**禁止**进 Redis 明文；若需缓存会话，只存加密后的短时 token，键名带项目前缀（若用 Redis：`aijobhunter:platform:...`）。

| 层级 | 要求 |

## 9. 风险与开放问题（需产品拍板）

1. **首平台选谁？** 猎聘 API / 本机导入 / 其他——决定阶段 B 工期。  
2. **Agent 跑哪？** 仅用户本机 vs 可选私有容器——影响安全模型。  
3. **全自动是否进 V2.0？** 建议默认不做，进 V2.1。  
4. **Cookie 谁保管？** 建议本机钥匙串 / 系统钥匙串，不进云库。
